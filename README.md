# Nuestra Historia

Gudo Labs nace de una pregunta:

¿Por qué una unidad puede indicar un porcentaje bajo
de ocupación volumétrica y aun así no tener capacidad
real para cargar más paquetes?

Esa pregunta abrió una investigación sobre:

- Capacidad matemática vs capacidad operacional.
- Flujo continuo vs planificación estática.
- Tiempo como restricción crítica.
- Sistemas capaces de aprender de excepciones.

---

# Nuestra Filosofía

No construimos software para impresionar.

No buscamos algoritmos perfectos.

Aprendemos de ellas.

No modelamos un mundo ideal.
